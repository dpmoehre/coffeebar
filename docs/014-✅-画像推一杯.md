# 014 · 画像反过来推一杯

> **状态**：✅ —— 画像带 `suggest`，页上「下一杯」只打开豆卡。
> **范围**：在已有画像上，从**在库**豆子里指出下一杯更可能对上这个人的。不是点单，不记消耗。
> **前置**：画像见 [002](002-🚧-豆子档案与小主机架构.md)、`stats.person_profile`。赏味窗见 [016](016-✅-烘焙日与赏味窗口.md)。

## 给接手 Agent

1. 先读「已定」。不要做成酒单、不要排队。
2. 一条队列任务一个 H1。
3. 建议跟画像走，只读，不占写锁。
4. 样本不足（现口径：不足 3 杯）继续写「还不够判断」，**不给推荐**。

## 已定（不要重开）

- **只推在库、未删、有未关袋的豆。** 历史豆、待入袋、别人的豆、广场卡都不推。
- **只推咖啡。** 酒以后再说，避免和酒单抢入口。
- **一条主推 + 最多两条备选。** 每条必须能用一句话说清为什么（「他近 10 杯浅烘高酸多，这支正当时，而且三天没喝过」）。说不清就不要这条。
- **点推荐只打开豆卡。** 不自动冲一次，不预填「谁喝的」（人可以自己去冲一次里点）。
- 最近 3 个业务日刚给这个人冲过的豆，大幅降权，避免总推同一支。
- 口味仍用他喝过的豆上的杯测加权（现有 `taste`：酸质 / 甜感 / 干香），不是他自己打的分。
- 011 落地后：同等口味下，`peak` 优于 `resting` / `fading`，`stale` 垫底；没填烘焙日不因此出局。
- 不做：协同过滤、社区别人的评价、付费排序、推库存为 0 的。

## 打分（实现时按这个顺序加，不要上模型）

对每支在库豆：

1. 烘焙：他近 20 杯里该烘焙度的占比，高则加分。
2. 口味：豆卡最近杯测的酸/甜/香，和画像 `taste` 的绝对差，差小加分。没杯测的豆不因此出局，只少一项。
3. 产地 / 处理法：近 20 杯里出现过的，轻微加分。
4. 新鲜：有 011 就按阶段加减；没有就跳过。
5. 重复：3 个业务日内喝过，重罚；从未喝过，轻奖。

同分看剩余克多的。推不出来（库空、或全被重复罚掉）就写「在库这几支暂时分不出先后」。
