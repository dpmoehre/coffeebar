# ✅ 已完成：后端骨架与数据层

## 落地内容

- `pyproject.toml` / `.python-version`：Python 3.13，依赖只有 fastapi、uvicorn、pydantic。不用 ORM、不用 Alembic——单机单文件，`schema.sql` 每次启动幂等执行就够。
- `app/schema.sql`：`bean` / `bean_lot` / `stock_event` / `consumption_event` / `person` / `tag` / `bean_score` / `brew_guide` / `write_lock`，以及豆卡 / 补货 / 冲煮过程照等照片表。
- `app/db.py`：连接、外键、WAL、业务日（凌晨 4 点分界）、统计期间起点。

## 三条硬口径的实现方式

- **账面剩余** = `可用克重 + Σ stock_event.delta_g − Σ 未撤回消耗.amount_g`
  - 可用克重 = `COALESCE(measured_g, nominal_g)`：**默认包装标称**，开袋实称有则取代
  - `intake` / `measure` 的 `delta_g` 记 0（`measure` 改的是 `lot.measured_g`，通过可用克重影响账面）
  - `adjust` 的 `delta_g` = 盘点值 − 当时账面；`close_lot` 的 `delta_g` = −当时账面（结清归零，偏差即这个数）
- **成本快照**：写消耗时把 `批次买入价 ÷ 可用克重` 冻结进那一行的 `unit_cost`，统计只读快照。
- **撤回**：只写 `voided_at` + 原因。批次若已关袋，另记一笔当天的 `adjust`（`delta_g = −amount_g`），关袋结果不被破坏。已撤回的行可以再彻底删除，库存不再动。

# ✅ 已完成：冲煮方案计算

`app/brew.py` 是纯函数，不碰数据库。总水 = `round(粉量 × 粉水比)`，各段按方式权重切分，**最后一段吃掉四舍五入的余数**，保证加总严格等于总水。四种方式：V60 四段、Hoffmann 一杯、4:6 粕谷、Kalita。每段给出本段用水、本段水粉比、累计秤到、累计水粉比、本段秒数、累计时间、手法、目标、功能、动画场景键。水粉比 = 克数 ÷ 粉量，两位小数，写作 `1:x`，和方程式称同一口径。

豆卡上只存默认值（`brew_guide`），方案每次按当场输入重算——改粉量或比例，各段立刻跟着变。

**验收**：`tests/test_brew.py` 对 4 种方式 × 5 组粉量比例做参数化，断言加总等于总水、目标克数与时间严格累加、末段一定是无水的滴滤；`test_stage_ratios_match_grams_over_dose` 钉住 15.9 g / 1:16 → 总水 254 g、累计比 1:15.97。

# ✅ 已完成：平均粉量与统计

`app/stats.py`。平均每杯粉量就近优先：**这支豆最近 20 杯 → 全局最近 50 杯 → 兜底 15 g**，同时给区间（只给一个平均值会掩盖波动）。杯数、见底提醒、这杯多少钱全部按它换算。

## 一处只有真跑起来才暴露的问题

FastAPI 把同步路由放线程池执行，`yield` 依赖的清理阶段可能落在另一个线程，导致 `sqlite3.ProgrammingError: SQLite objects created in a thread can only be used in that same thread`。单测用的 `TestClient` 复用线程，掩盖了它。修法是 `check_same_thread=False`——每个请求独占一个连接、不共享，放开这个检查是安全的；同时加 `busy_timeout` 避免写撞上直接报 locked。这也是保留 `scripts/smoke.py` 的原因：它对着真 uvicorn 跑。

# ✅ 已完成：人可以真删掉

原先 002 写的是「停用不是删除，真删会让历史流水失去归属，不做」。这条被推翻了——**人必须能删**。

改法是把「删人」和「删记录」拆开：`DELETE /api/people/{id}` 真的删掉 `person` 那一行，但先把他名下 `consumption_event.person_id` 置空。那些豆是真扣过的、钱是真花过的，删个人不该让库存账和统计总数跟着变，所以流水留下来变成「没记」。每条失去归属的行都写一笔 `consumption_audit`，以后还能回答「这笔以前算谁的」。

界面上删之前会说清有多少条会变「没记」；想把记录留给别人，先「改归属」挪走再删。「停用」保留为轻量选项（只是从选人列表收起来）。

**验收**：`tests/test_stats.py` 与 `tests/test_api.py` 共 8 个用例，钉住「删人后 `cups` / `beans_g` / `spent` / 批次账面全部不变，那笔归到『没记』」；`scripts/smoke.py` 第 11 步对真服务复核一遍。

- **只建豆卡还没入袋**：不填 `nominal_g` 就只建卡。这种豆一袋都没有，既不算在库也不算喝完，`pending=true` 跟着「在库」出并标「待入袋」，否则刚建的卡会直接掉进历史里找不着；也不进补货清单（豆子在手上，缺的是称重录入，不是缺货）。
