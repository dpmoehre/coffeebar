## 方向变更（2026-09-05 定）

原口径是**单人自用、内网为主**，002「第一期不做」里明确排除了账号体系、多角色权限和常驻公网。本轮用户改主意，要把网页发布出去做成社区：

- **公开范围**：整套搬上云，**每个人都有自己的私库和账本**；只有**豆种**与**评价**是公共的。
- **注册**：面向互联网**开放注册**（先小范围也行，但设计按开放做）。
- **托管**：用户无发布经验，采用「GitHub 自动部署的平台 + 托管 Postgres + 对象存储」，不自建服务器、不上 Docker。

002 不改写历史结论（第一期确实没做），转向记在本文件。**切换日之前**小主机 `data/` 仍是唯一真库存。上云后云是唯一正库，小主机改连云，不做两套并存、不做双向同步。

## 核心拆分：豆卡要一分为二

现在 `bean` 同时承担两件事，社区化必须拆开：

| 层 | 是什么 | 谁可见 |
| -- | ---- | ---- |
| **公共豆种** | 「MATYAZO CWS 黑莓可可」这支豆本身：产地、豆种、处理法、烘焙度、店家豆卡 | 所有人；评价挂在这一层 |
| **我手上那袋** | 袋子、进价、剩余克重、消耗流水、谁喝的 | 只有本人 |

不拆的后果只有两种：要么别人看见你的进价，要么评价挂在你的私人豆卡上、别人无法评。

## 已核对的技术缺口

1. **没有归属列**：`bean`、`bean_lot`、`stock_event`、`consumption_event`、`bottle`、`bottle_lot`、`bean_score`、`person`、`brew_guide`、`restock_rule`、两张 photo 表都没有 owner。`store.py` / `spirits.py` / `stats.py` 的每条查询都是全库，需要逐条加归属过滤。
2. **接口外泄金额**：`/api/beans`、`/api/spirits` 每行带 `unit_cost`、`last_price`、`balance_g` / `balance_ml`。公共视图要另一套不含钱与库存的序列化。
3. **写锁语义变了**：`locks.py` 的软锁「一键接管」前提是同一个人的多设备。私库天然单主人，锁可保留；**公共豆种的编辑不能让陌生人互抢**，要另设机制（管理员改 / 提修改建议）。
4. **`bean_score` 没有作者**：评价要带 `author_id`，并定「一人一豆一条可改」还是「允许多条」。
5. **SQLite 绑死**：`app/db.py` 的 `ADDED_COLUMNS` + `STALE_CHECKS` 重建表是手写 SQLite 迁移，`schema.sql` 也是 SQLite DDL。上云要迁 Postgres，迁移层需重做。
6. **照片在本地磁盘**：`photos.py` 写 `data/photos/` 并生成缩略图，云上要换 S3 兼容存储。
7. **`person` 不是账号**：「谁喝的」是可改名可停用的标签实体，不能直接当用户。要定它和账号的关系（可关联，也可保持纯标签）。

# ✅ 已完成：登录加固（Argon2 / 限流 / 验证邮箱 / 找回密码）

骨架仍是手写登录，只换容易写错的零件，不引入 fastapi-users / Better Auth。

- **密码**：新哈希用 `argon2-cffi`。旧库 `pbkdf2_sha256$…` 登录成功后升成 Argon2。
- **限流**：注册 / 忘记密码按 IP 每分钟 5 次（进程内）。**登录只数输错的**，网页给 5 次机会，登对了不占次数；网页和 MCP 分开计，Cursor 连不上不会把网页登录次数用光。测试套件设 `COFFEEBAR_RATE_LIMIT=0`；单独有一条打开限流的用例。
- **验证邮箱 / 找回密码**：`auth_token` 一次性、2 小时过期。配了 `COFFEEBAR_SMTP_HOST` 就发信，响应不带链接；没配（默认，小主机也是这样）把 `verify_url` / `reset_url` 放进 JSON，页面上能点。`forgot` 对外始终 200，避免探邮箱。重置成功清掉该账号全部 session。
- **验证不挡登录**：没配 SMTP 时注册即视为已验证。配了 SMTP 才先标未验证。老库补 `email_verified` 列时默认 1，避免小主机升级后全员变成「没验证」。
- **Cookie**：HttpOnly + SameSite=Lax；HTTPS 或 `COFFEEBAR_COOKIE_SECURE=1` 时开 Secure。
- **网页**：登录页可忘记密码、设新密码；`/?verify=`、`/?reset=` 打开即走对应流程。未验证账号侧栏可再发一封。

公开链接用 `COFFEEBAR_PUBLIC_URL`，没有则用请求的 `base_url`。

**验收**：`uv run pytest` 含 Argon2 落库、旧哈希升级、忘记并重置后旧密码失效且旧 session 作废、未知邮箱不回链接、验证链接一次性、登对了不占次数、网页第 6 次错误登录 429、MCP 连错不影响网页这 5 次、强制 Secure 时 cookie 带该标记。

## 域名 / 证书 / 备案（已调研，结论先记着）

- **前两期不买域名**：直接用平台送的子域名（`xxx.onrender.com`、`xxx.up.railway.app` 之类），自带 HTTPS，零成本、无需备案，足够开发与内测。
- **证书永远不花钱**：Let's Encrypt / ZeroSSL 已是标准，平台与 Caddy 都自动签发续期。只有 OV/EV 企业身份展示才需付费，本项目不需要。
- **买域名看续费价**：`.xyz` / `.top` 一类首年一两美元、续费翻几倍；长期还是 `.com` 稳。注册商优先 Cloudflare Registrar（成本价、无推销）或 Porkbun。
- **备案只有一种情况需要**：服务器在**中国大陆**（阿里云 / 腾讯云国内地域）。放海外或香港不需要备案。
- **若决定备案，域名必须在国内有资质的注册商买**（阿里云 / 腾讯云），先实名认证，且顶级域要在工信部许可名单内 —— Cloudflare Registrar 买的域名无法备案。
- **本项目的备案风险**：开放注册 + 用户上传图文评价属于 UGC / 社区类，各省对**个人备案**的互动功能审核宽严不一，经常被驳回；企业备案（营业执照）才顺。加上 ICP 备案后 30 天内还要公安备案，整体 2–4 周。
- **暂定路线**：**海外托管 + 不备案**。国内访问慢可用 Cloudflare 缓解；等真有大陆用户规模再谈备案与企业主体。
