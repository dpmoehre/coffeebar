# ⌛️ 未完成：异地备份

## 目标

每天（或每次启动后）有一份能还原的 zip：**不在小主机系统盘上**。现有 `scripts/backup.bat` / `scripts/backup.sh` 继续用 SQLite 在线 `backup()`，不要改成直接拷 WAL 文件。

## 现状

- 脚本：`scripts/backup.bat` → `%USERPROFILE%\coffeebar-backup`；`scripts/backup.sh` → `$HOME/coffeebar-backup`。
- 002「数据落点与备份」写了「拷到另一块盘」，**没有定时、没有离开本机**。
- 小主机真库存曾从 `D:\data` 覆盖进来；`D:` 若还在，优先当异地盘，不要只写 C: 用户目录。

## 设计

1. 保留「点一下出 zip」给人手备份。
2. 增加可选目标：环境变量 `COFFEEBAR_BACKUP_DIR`（U 盘、群晖挂载、第二块盘）。没设就仍写用户目录，但启动或备份结束要印一行警告：`这份备份还在本机，盘坏会一起没`。
3. 定时：Windows 用「任务计划程序」说明写进本节或 `scripts/README` 一段即可，不要做常驻服务。Mac / Linux 写 `launchd` / cron 示例。默认每天一次够用。
4. 不要把 WebDAV / cpolar 账号写进仓库。若走群晖，用本机已挂载的路径或本机 `.env`。
5. zip 格式保持与现在一致（根下 `coffeebar.db` + `photos/`），以便以后 009 的 `restore` 仍能吃。

## 验收

- 设了 `COFFEEBAR_BACKUP_DIR` 时，zip 出现在那个目录，且 `sqlite3` 能打开里面的库。
- 没设时脚本仍成功，stderr/stdout 有「还在本机」警告。
- 服务开着备份不报 locked（沿用 `sqlite3.Connection.backup`）。
- 手工：小主机跑一次，确认第二块盘或群晖上有当天文件。写入 006。

## 风险

- 定时任务失败没人看。第一版至少备份结束打本地日志；能弹窗更好，不做监控平台。
- 不要为了异地去实现双向同步。

# ⌛️ 未完成：第一人接手必须确认

## 目标

有孤儿数据时，谁先注册也不能在不知情下领走吧台账本。默认是空库；接手是显式动作。

## 现状

- `app/auth.py` `register()`：`account` 表为空则 `claim_orphans()`，把 `bean` / `bottle` / `person` 里 `owner_id IS NULL` 的行全部挂到新账号。
- 登录页副文案只提示「第一个注册的人会接手」，没有勾选、没有二次确认。
- 005 把这套静默接手标成已完成（为了小主机升级后库存还在）。**升级场景仍要能接手**，但必须点头。

## 设计（接口）

1. `POST /api/auth/register` **不再自动 claim**。
2. 请求体增加可选 `claim`：`"take"` | `"leave"` | 缺省。
3. 注册时若存在孤儿（`owner_id IS NULL` 的豆或酒或人）：
   - 没带 `claim` → **400**，正文说明还有没主人的库存，并带上数量 `{beans, bottles, people}`，让页面弹出二选一。不要用 409（409 已表示邮箱占用）。
   - `claim=take` → 建号并 `claim_orphans`，响应 `claimed: true`（与现在字段兼容）。
   - `claim=leave` → 建号、**不** claim，孤儿继续 `NULL`。响应 `claimed: false`。
4. 没有孤儿时忽略 `claim`，行为与现在「普通注册」相同。
5. **谁还能再接手**：孤儿留下之后，只有「本机已登录且库里仍无任何 `owner_id` 非空」或「仍是第一个账号」可调 `POST /api/auth/claim-orphans`（仍要密码或当前 session）。第二、第三个新注册的人即使带 `claim=take` 也 **403**，避免客人领走吧台。若第一个人选了 `leave`，由他登录后再点接手。
6. 本机邀请码（`COFFEEBAR_INVITE_CODE`）与本条正交：有邀请码仍先校验邀请码，再走 claim 选择。

## 设计（网页）

- 注册提交后若 400 带孤儿数量：模态「这台机器上还有 N 支豆、M 瓶酒。接手吧台账本 / 只要空库」。
- 「接手」用强调色；「只要空库」是次要按钮，并写「库存还在机器上，不会挂到这个号」。
- 第一个号若选了留下，侧栏或登录后给一条持续提示「还有没主人的库存」，点进去才能 claim。不要只靠注册那一次。

## 验收

- 机器：空库注册不弹；有孤儿不带 claim → 400 且库未被领；`take` 领走且第二个账号 `take` → 403；`leave` 后第一人登录再 claim 成功。
- 手工：空号对一份带孤儿的临时库走一遍两按钮。不要在小主机真库存上试 `leave` 除非你知道怎么再 take。写入 006。

## 不要做

- 不要改成「必须邀请码才能注册」来代替本条（那是 005 / 009 的公网闸门）。
- 不要自动把孤儿挂到「看起来像管理员」的邮箱。

# ⌛️ 未完成：真库存号注销前导出

## 目标

侧栏「注销账号」仍可清掉**自己的**私库，但接手过孤儿、或当前仍握有从本机迁来的豆/酒的号，必须先拿到备份。服务端是闸门，不能只靠文案。

## 现状

- `POST /api/auth/delete`：再验邮箱+密码，然后 `delete_account` 物理删豆/酒/人/照片/流水/账号。临时 `PRAGMA foreign_keys = OFF`。
- 前端模态已写「不可恢复」「接手真库存的号等于清吧台」，没有强制下载。

## 设计

1. 判定「真库存号」：该账号曾经 `claimed`（建议 `account` 加 `claimed_at`，老号用「名下有豆或酒」兜底）。不要只靠前端记。
2. 真库存号 `POST /api/auth/delete` 若没有有效的导出凭证 → **400**「先导出备份」。
3. 导出：已登录可 `GET /api/ops/backup`（或复用现成打包函数）下载与 `backup.sh` 同结构的 zip，只含**自己的**库切片太重的话，第一版允许打**整份** `data/`（单机一人真库存时就是整份）。响应同时发一次性 `export_token`（短 TTL，如 15 分钟），注销请求必须带上。
4. 空号、从未接手、名下无豆无酒：保持现在的「邮箱+密码即可注销」，不必导出。
5. 文案改成两步：先「下载备份」，再「确认注销」。下载失败不能点确认。

## 验收

- 机器：空号无库存直接注销；有豆的号不带 token 400；带过期 token 400；带新 token 才删光且 zip 能打开。
- 手工：只拿空号或【测试】号。真库存号只测到「不带备份被拒」即可，不要在小主机上真注销。写入 006。

## 不要做

- 不要改成软删除账号却继续占邮箱（除非另开任务）。本条只加闸门，不改 005 的「删了邮箱可重注册」。
- 不要在注销事务里继续关外键还不包事务；能一并包进「账面多步事务」更好，但本条以闸门为完成条件。

# ⌛️ 未完成：账面多步事务

## 目标

一笔业务（撤回已关袋、整袋改价再关袋、删卡 keep/wipe、注销删数据）要么全成，要么全不成。崩溃或 Windows 锁库时不要留下半截账。

## 现状

- `app/db.py` `connect()`：`isolation_level=None`（自动提交），`busy_timeout=4000`。
- `store.py` / `spirits.py` / `auth.delete_account` 连续多条 `execute`，全文件没有 `BEGIN`。
- 小主机注销曾因多连接锁库 500（已改成单连接，但仍然无事务）。

## 设计

1. 保持 `isolation_level=None`（与现有 PRAGMA/脚本兼容），在业务函数里显式：
   - `conn.execute("BEGIN IMMEDIATE")`
   - 成功 `COMMIT`，异常 `ROLLBACK` 后原样抛出。
2. 用一个小助手（如 `app/db.py` 里 `transaction(conn)` 上下文管理器），不要每个路由手写 try/finally 还漏。
3. 至少包住：
   - `store.void_one` / `unvoid_one` / `delete_voided_one` 以及酒单整巡对应函数
   - 整袋改价再关袋（`store` 里改 `nominal_g`/`price` 再 writeoff/close 的那段）
   - `store` / `spirits` 的删卡 keep/wipe
   - `auth.delete_account`（照片文件删除放事务外或先列路径、提交成功后再删文件；失败不要先删光照片）
4. 读请求不要开 IMMEDIATE。
5. 单测：在事务中途故意失败（mock 第二次 execute），断言库回到原状。

## 验收

- `uv run pytest` 原有账面/撤回/删卡用例全过，再加「中途失败回滚」至少 2 条。
- 手工：不必测成功路径；若在小主机复测注销，只用空号。

## 风险

- 长事务会加大 `database is locked`。IMMEDIATE 先拿写锁，比半截提交更安全；`busy_timeout` 可提到 8s，先量再调。
- `executescript` 与显式事务不要套娃。迁移代码（`init_db` / `_rebuild`）本条不动。
