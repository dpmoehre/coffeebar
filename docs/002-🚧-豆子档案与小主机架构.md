# ✅ 已完成：产品定位与运行环境

## 这是什么

公司里的个人手冲 / 调酒吧台。用途是**自己做手冲咖啡、偶尔调酒时，把豆子档案管清楚**。

第一期只做豆子：

- 豆卡：产地、风味、当前克重
- 每次消耗记流水（冲一次扣多少克）
- 冲煮指导（分步文字 + SVG 动画播放）
- 拍照或选图上传豆子图片（手机最方便，各端都能传）

酒水与调酒配方留到第二期，表结构预留品类扩展，第一期不做界面。

## 明确不是

- 不是给同事点单、排队、支付的系统
- 不是后厨 KDS
- 不是多门店 / 公司 SSO

## 谁在哪用

**功能全端一致**：小主机、手机、其他电脑、cpolar 远端都能查豆、改豆卡、记消耗、上传照片、播放冲煮动画。差别只在**页面布局**（桌面宽屏分栏 / 平板 / 手机单列），不按设备砍功能。

| 场景 | 设备 | 布局（功能相同） |
| ---- | ---- | ---- |
| 日常吧台 | 小主机自带屏幕 + 键鼠 | 桌面宽屏：豆库网格 + 豆卡侧栏或双栏 |
| 手里拍照、站着冲 | iPhone / iPad | 单列大按钮；相机入口更靠前，冲煮动画占满屏 |
| 换一台电脑 | 内网 Mac / Windows | 同桌面布局，随窗口宽度收成单列 |
| 外出临时 | cpolar | 与对应设备布局相同 |

拍照仍以手机最方便，但电脑也能选文件上传。冲煮动画在吧台大屏和手机上都能完整播放。

**不能有多端竞争**：功能可以都有，但**同一时刻不能两台设备同时改同一条数据**。细则见「无多端竞争」。

## 小主机（唯一服务器）

| 项 | 值 |
| -- | -- |
| 系统 | Windows 11 |
| CPU | Ryzen 7 PRO 7850H + Radeon Graphics |
| 内存 | 16 GB |
| 交互 | 自带屏幕，平时本机键鼠操作 |
| 网络 | 公司内网为主；必要时用 **cpolar** 做临时外网代理 |
| 角色 | 既是服务器，也是日常使用的工作台 |

这台机器算力充裕，架构按**单机单体**做即可，不必上集群、不必上独立对象存储。16 GB 同时跑 Win11 桌面 + 本应用足够；**默认不用 Docker Desktop**（少占内存、少一层 WSL2），本机用 `uv` / `npm` 跑进程，开机自启。

# ✅ 已完成：软件架构方案

## 形态

一套响应式网页，一台小主机跑完。不写四套原生 App。

```
[小主机 / 手机 / 其他电脑 / cpolar]
  同一套功能：豆卡 · 库存 · 照片 · 冲煮动画
  只换布局，不换权限
        │
        ▼
   Caddy :80 ── FastAPI ── SQLite + photos
                 │
                 └── 写锁：同一条豆卡同时只允许一个写会话
```

小主机上只保留三件事：

1. **反向代理**：Caddy（本机 80，转给应用端口）
2. **应用进程**：FastAPI 提供 API，并托管前端构建产物（或 Vite 开发时拆开）
3. **数据**：SQLite 单文件 + 本地图片目录

不引入微服务、消息队列、云 OSS、独立用户中心。

## 无多端竞争（硬约束）

多端**功能完整、布局不同**。禁止的是「两台设备同时改、互相覆盖」，不是「手机只能看」。

不做实时协同、不做 OT/CRDT、不做 last-write-wins 互踩。

服务端按**资源写锁**强制（按豆卡，而不是按设备类型）：

- 任一端开始改某条豆卡 / 记消耗 / 改指导 / 改照片时，持有该豆卡的短时写锁。
- 其他端仍可**完整浏览、播放冲煮动画**；若再提交同一条的写操作，拒绝并提示「另一台设备正在编辑这条豆」，不合并。
- 锁释放：保存成功、取消编辑、或超时。播放冲煮动画**不占写锁**（只读播放）。
- 本机多标签同样适用：同一条豆卡同时只接受一个写会话。
- SQLite 单文件单写者与此一致；不做多端会话协商以外的同步协议。

## 技术栈（已选定）

与仓库约定一致：Python 用 **uv**，前端用 **npm**，密钥与运行数据不入库。

- **前端**：Vite + React + Tailwind（设计 token）+ [anime.js](https://animejs.com/documentation/svg)（页面动效与冲煮 SVG）。**一套组件、响应式布局**：桌面宽屏 / 平板 / 手机只改栅格与触控尺寸，不拆第二套功能。
- **后端**：FastAPI（`uv`）。豆卡 CRUD、图片上传与转码、库存流水、冲煮指导、按豆卡的写锁。
- **数据库**：SQLite（例如小主机上的 `data/coffeebar.db`）。备份 = 拷文件。
- **图片**：`data/photos/`，不进 Git。iPhone 常见 HEIC，服务端转 JPEG/WebP 并生成缩略图。
- **入口**：内网 `http://小主机名或局域网IP`；本机也可 `http://localhost`。
- **进程**：Windows 开机启动（任务计划或 NSSM 一类服务），不要依赖每次手动开终端。
- **口令**：环境变量注入的简单口令，防止同事误改库存。cpolar 打开时必须有口令，且 token / 口令不入库。

备选（未采用）：Next.js 全栈。功能等价，但和「Python 用 uv」分叉，除非后续明确改口。

## 第一期信息结构

```
Bean 1──* BeanPhoto
Bean 1──* InventoryEvent    # 入库 / 消耗 / 校正，单位克
Bean 1──* BrewGuide         # 可多套器具或多套手法
```

豆卡字段（第一期）：

- 名称、产地、处理法、烘焙度、烘焙日期、风味描述
- 当前克重（由流水汇总，允许记一笔「校正」）
- 照片（至少一张主图）
- 冲煮指导：器具、粉量、水量、研磨、水温、**分步时间轴** + **动画场景键**（见下节）

页面保持少（全端都有，布局不同）：

1. **豆库**：图、名字、剩余克重、风味标签（桌面网格 / 手机卡片列表）
2. **豆卡**：产地 / 风味 / 库存 / 照片 / 冲煮动画 / 消耗记录
3. **拍照或选图**：手机走相机，电脑走文件选择，同一上传接口
4. **冲一次**：填本次克重，写一条消耗流水；可从冲煮播放结束顺手记消耗

「每次消耗量」做成流水，不只改一个数字：能看当前剩多少，也能回看哪天用了哪只豆、用了多少克。

## 网络

- **默认**：只走公司内网。小主机与手机连同一局域网即可上传照片。
- **cpolar**：仅在需要外网打开时临时开隧道，指向本机 Caddy/应用端口。不把 cpolar 写成常驻架构，不把隧道地址或 token 写进仓库。
- 开隧道期间视为半公网：口令必开；能关则关。日后若改固定域名再谈正式 HTTPS，不阻塞第一期。

## 数据落点与备份

- 代码在本仓库；**运行数据只在小主机 `data/`**，`.gitignore` 排除。
- 备份：定期拷贝 `data/coffeebar.db` + `data/photos/` 到另一块盘或个人网盘。
- 照片不走云 OSS，避免公司环境绑外网账号。

## 第一期不做

- 点单、排队、支付、KDS
- 公司 SSO、多角色权限
- 常驻公网、复杂证书体系（cpolar 只作临时通道）
- 酒水库存与调酒配方界面（仅预留 `kind=bean|spirit` 一类扩展位）
- 多端同时可写、实时协同、冲突合并（功能全端都有，但不能同时改同一条）
- 按设备砍功能（例如「手机只能补图」）

# ✅ 已完成：全端布局、统一 UI、冲煮动画

## 功能 vs 布局

- **功能**：所有屏幕同一套路由与接口（豆库、豆卡、照片、消耗、冲煮播放/编辑）。
- **布局**：用断点换排版。小主机宽屏双栏、手机单列全宽动画、平板介于两者。
- **动效**：同一套 anime.js 时间轴；用 `createScope` + media query 只调整位移/尺寸，不维护两套动画逻辑。文档：[Anime.js Scope / 响应式动画](https://animejs.com/documentation/svg)（站点内 Scope 与 SVG 同属 v4 工具箱）。

## UI 风格（全站统一）

现代吧台，而不是后台表格风。全站共用一套 token（色、字、圆角、阴影、动效时长），禁止单页另起一套皮肤。

方向（落地时写成 CSS 变量，可微调，不另开主题系统）：

- 深色底（espresso）+ 奶油字 + 琥珀色点缀；卡片轻玻璃/软阴影。
- 大字号、少边框、豆卡照片做主视觉。
- 列表进入用 stagger；按钮/卡片有短反馈，不堆无意义循环闪烁。
- 字体与间距全站同一套；冲煮播放页也走同一色板，不做成「突然另一个 App」。

参考（只借交互与气质，不抄页面、不入库他人资源）：

- [Anime.js SVG](https://animejs.com/documentation/svg)：`createDrawable` 描线、`createMotionPath` 沿路径、`morphTo` 形变；官网示例把壶/车沿赛道走、把 path `draw` 从 `0 0` 画到 `0 1`。
- [Toololis Pour-Over Timer](https://toololis.com/pour-over-coffee-timer/)：V60 水位涨落 + 滴滤虚线 + 四段（闷蒸 / 一注 / 二注 / 滴滤）进度点。
- [Angus Pour Over Timer](https://anguszhu.com/pour-over-timer/)：全屏阶段进度、一眼能看「现在该注到多少克」。
- [stromland/coffee](https://github.com/stromland/coffee)：深色咖啡仪表盘气质（仅作配色/信息密度参考）。

## 冲煮动画指导

冲煮指导不只是文字步骤，而是**可播放的分步动画**（吧台对着冲、手机对着冲都要能用）。

第一期器具以手冲漏斗（V60 一类）为主，步骤绑定动画场景键，例如：`bloom` / `spiral` / `center_pour` / `drawdown`。每步带目标克重与秒数。

技术约定（anime.js v4 SVG，见[官方 SVG 文档](https://animejs.com/documentation/svg)）：

- **`createDrawable` + `draw`**：描出滤杯轮廓、注水螺旋、滴滤虚线。
- **`createMotionPath`**：壶嘴/水线沿螺旋路径走，对应「绕圈注水」。
- **`morphTo`**：水位面、粉床形状在闷蒸与注水之间过渡。
- **`createTimeline`**：按豆卡里的分步秒数串起来；可暂停、跳步、重来。
- 动画资源用本仓库自绘 SVG（简单几何即可），不依赖外网素材。

播放时：当前步大字提示「注到 xx g / 还剩 ss」、动画与计时同步。播完可一键记消耗（粉量默认带出指导里的 dose）。
