# coffeebar

公司咖啡吧里的**个人手冲 / 调酒工作台**。远程：[github.com/dpmoehre/coffeebar](https://github.com/dpmoehre/coffeebar)。

用来把豆子和酒管清楚：豆卡、照片、库存、冲煮怎么倒、谁喝了、一杯多少钱、该补货了；酒有酒单、酒瓶、鸡尾酒和基酒配方；还能看日历、出表、按人出画像。

**不是点单点菜，不是后厨 KDS，也不是给全公司下单的系统。**

**豆子部分已经能跑**（豆库、豆卡、批次、冲煮、消耗、撤回、补货、统计、画像）；酒和 MCP 还没开工。约定与数据模型见 [docs/002-🚧-豆子档案与小主机架构.md](docs/002-🚧-豆子档案与小主机架构.md)，实现进度见 [docs/003-🚧-豆子第一期实现.md](docs/003-🚧-豆子第一期实现.md)。页面气质可点 [_Doc/2026-09-04-ui-样张/index.html](_Doc/2026-09-04-ui-样张/index.html)。

## 能做什么

### 豆子

- **独立豆库**：一眼看所有在库豆子还剩多少，带进度条。21 寸吧台屏按四列排。用完的豆进「历史」，风味和冲煮记录保留。
- **排序与筛选**：浅/中/深烘、酸甜香、剩余、评分、地区、水温、开封日；自由标签点一下就筛。
- **豆卡**：产地、处理法、风味、杯测雷达、价格、每杯成本。照片分包装袋和豆盘，没开封可以先缺豆盘图。同样的豆再买只「再入一袋」，不用新建卡。库存用图标显示袋数、克数、杯数。
- **还剩多少克**：这是库存区最主要的信息——直观看还有多少量、还能冲几杯、要不要补。刚拆袋通常不会去称，**默认就按袋上印的标称克重开始扣**；想较真时才补一笔开袋实称。见底只提醒；「这袋用完」要人确认，偏差记进流水。
- **平均一杯用多少粉**：每次冲煮记的是**当次实际用量**（不是每次都写 15 g），系统再从这些实际值统计出「我平均一杯用多少粉」并给出区间。豆库和豆卡的「还能冲几杯」、见底提醒、这杯多少钱，全都按这个数换算，不用假想值。
- **消耗**：冲一次时**自己选用哪一袋**（列出各袋的剩余、单价、开封日，不自动挑），扣克重并记「谁喝的」。消耗速度画曲线，低库存进补货清单；补货条目可上传对照图片。
- **谁喝的可以随便管**：人能新增、改名、停用（改名不动历史，停用不删记录）；每个人有一页追踪记录。记错了能**撤回**——库存加回去、钱退出统计，流水只划掉不删，账目仍可追溯。
- **冲煮指导**：单独占一整行（不和库存挤宫格）。按你当场输入的粉重和粉水比即时算每一段的用水、秒数、累计时间、手法、目标与功能；豆卡上只存默认值，可播放动画并记下实际用时。

### 酒

- **基酒**：酒名、买入价、风味类型、酒精度（% vol）列在一起能看见；同样的酒再买只加一瓶，不新建名字。
- 推荐酒单、鸡尾酒配方、自制基酒（浸泡/糖浆）配方。
- 倒一杯记毫升；和豆子共用「谁喝的」与补货清单。

### 统计与画像

- **统计**：一进来先看数字——这段时间消耗了多少克豆子、平均一杯用多少粉、多少毫升酒、酒精大约多少克、喝掉多少钱、买进来多少钱、多少杯；再看曲线和按人拆开。撤回的流水不进任何汇总。
- **日历**：哪天冲了咖啡、哪天喝了酒。
- **出表**：CSV（Excel 能直接开），含库存、流水、分数、标签、关袋偏差、统计汇总。
- **用户画像**：按人名从流水自动总结爱喝什么样的（浅烘高酸、常点的酒等），并写出这个人喝了多少克豆、多少酒精、花了多少钱。样本太少不强行下结论。

### Cursor 用 MCP 直接记账

准备好豆袋照片和豆卡文字后，可以让 **Cursor 经 MCP 直接写入** 小主机上的库，不必在网页里一项项手填。网页和 MCP 走同一套接口与写锁，写完刷新豆库就能看见。

计划中的能力（落地后在 Cursor 里打开本仓库的 MCP）：

| 你在 Cursor 里说 | MCP 去做 |
| ---- | ---- |
| 用这张图和下面字段建一张豆卡 | 建豆、建批次、拷照片进 `data/photos/` |
| 给西达摩补开袋实称 198 g | 改当前批次 |
| 我刚才用了 16 g，谁喝的：小王 | 记消耗流水 |
| 这袋冲完了 | 关袋并结清偏差 |
| 豆库还剩哪些浅烘 | 查询列表 |
| 这个月喝了多少豆、多少酒、花了多少钱 | 汇总统计数字 |

MCP 只连本机（或公司内网）上的 coffeebar，口令与数据不进 Git。详细工具表见 [docs/002](docs/002-🚧-豆子档案与小主机架构.md)「MCP：让 Cursor 接管记账」。

## 谁在哪用

| 场景 | 设备 | 差别 |
| ---- | ---- | ---- |
| 日常吧台 | Win11 小主机 + 21 寸屏 + 键鼠 | 宽屏布局，这是主屏 |
| 拍照、站着冲 | iPhone / iPad | 单列、相机和冲煮动画靠前 |
| 换一台电脑 | 公司内网 Mac / Windows | 同一套功能，随窗口变布局 |
| 外出 | 必要时临时 cpolar | 功能相同，必须有口令 |

功能全端一样，只换布局。同一条豆卡/酒瓶同时只允许一个写会话，避免互踩。自己在另一台机器上开着编辑页时，这边会问「要接管吗」，点一下就能改，不用干等；Cursor 经 MCP 写入则会被直接拦下，让你先去网页保存。

**小主机**：Windows 11，16 GB，Ryzen 7 PRO 7850H + Radeon。既是服务器也是工作台。内网为主。

## 怎么跑

不用 Docker。小主机上只要三个脚本：

1. **装一次**：双击 [`scripts/install.bat`](scripts/install.bat)。会装 uv、同步 Python 依赖、装前端依赖并构建。没有 Node 会提示你去装 LTS。
2. **日常用**：双击 [`scripts/start.bat`](scripts/start.bat)。自动开浏览器，同时打印内网地址，手机连同一个 Wi-Fi 输那个地址就能用。关掉窗口就停。
3. **备份**：双击 [`scripts/backup.bat`](scripts/backup.bat)。服务开着也能安全导出，库文件和照片打包进 `%USERPROFILE%\coffeebar-backup`。

想用 `http://coffee` 这种短地址而不是带端口的，再加 Caddy：`caddy run --config scripts/Caddyfile`。

### 在 Mac / Linux 上开发

```bash
uv sync                                    # 后端依赖
uv run uvicorn app.main:app --reload       # API 在 :8000
cd web && npm install && npm run dev       # 前端在 :5173，自动代理 /api
```

跑测试与端到端自检：

```bash
uv run pytest                    # 75 个用例：账面、成本快照、撤回、平均粉量、写锁
uv run python scripts/smoke.py   # 对着真在跑的服务走一遍完整场景并打印数字
```

数据都在 `data/`（SQLite + 照片），不入库。换机器：拷仓库 + 拷 `data/` + 再跑一次 `install.bat`。密钥和口令写本机 `.env`，不要提交。

## 技术形态

- 网页：Vite + React + Tailwind v4 + anime.js（冲煮 SVG）。构建产物由服务直接托管，不另起前端进程。
- 服务：FastAPI（uv）+ SQLite（标准库 `sqlite3`，WAL，无 ORM）+ 本地照片目录。
- 入口：默认 `:8000` 直连；想要短地址再上 Caddy。
- MCP：本机进程，调用同一套 FastAPI / 同一份 SQLite（未开工）。
- 视觉：深色 espresso、奶油字、琥珀点缀；样张以 [_Doc/2026-09-04-ui-样张/画像.png](_Doc/2026-09-04-ui-样张/画像.png) 为准。
